OpenAI 兼容接口，按集群路由

推荐使用 POST /v1/chat/completions，可直接作为 OpenAI SDK 的 base_url=http://你的地址:9010/v1。兼容入口： /router/call-manage/chat/completions、 /api/v1/call-manage/chat/completions。请求体保持标准 OpenAI chat/completions 格式，model 建议留空，由服务端按 X-Async-Type 指定的集群选择模型。

接入地址

Base URL 与端点

推荐：POST /v1/chat/completions（OpenAI SDK 直接可用）

兼容：POST /router/call-manage/chat/completions

兼容：POST /api/v1/call-manage/chat/completions

支持 stream: true（SSE 原样透传）与普通 JSON 响应。模型名称、API 地址与 API Key 均在管理页配置，调用方无需接触上游地址。

模型列表：GET /v1/models（返回可用模型与集群）；内置聊天页：/chat。

鉴权

项目 Token 或上游 Key

推荐：在「项目与密钥」创建项目，签发 sk-gw-... Token， 请求头使用 Authorization: Bearer sk-gw-...。网关只会用服务端配置的上游 Key 转发，Token 本身不会发给厂商。

带 sk-gw- 前缀的 Token 一定会被校验；无效、吊销、过期直接 401。 设置 GATEWAY_TOKEN_REQUIRED=1 后，不带 Token 的请求也会被拒绝。

兼容旧用法：不带 sk-gw- 前缀时，主链（X-Purpose 缺省 main）仍可用 Authorization: Bearer <上游 key> 覆盖服务端 Key；异步链强制使用服务端 Key。

项目 Token 与配额

按项目隔离调用量、Token 与成本

项目可设置每日 / 每月 调用次数、Token 数和成本上限。留空 = 不限，0 = 禁止调用。 调用次数在请求前检查；Token 和成本在响应后累计，属于软限额，最多超出一个请求。

成本只累计与项目币种一致的调用记录，不做汇率换算。Token 允许按模型名限制， 支持 * 通配，例如 gpt-*, deepseek-*；留空表示不限。

配额超限返回 429，错误格式为 {"error":{"code":"daily_call_quota_exceeded", ...}}。 成功响应会带 X-Request-Id、X-Gateway-Model、 X-Gateway-Cluster、X-Gateway-Retry-Count，便于排查。

请求头

路由头、思考与 JSON 输出控制
请求头取值说明
X-Async-Type async1..async9 模型集群。主链建议 async1，异步链建议 async2；同集群内轮询
X-Purpose main（默认）或任意以 async 开头的标识 异步判定、日志与 token 用量记账，不影响集群选择；建议 ≤16 字符
X-Thinking 1 / 0 思考模式开关；仅在模型「思考模式」为跟随请求时生效
X-Response-Format json_object 要求 JSON 输出（服务端按实际模型决定是否注入）
X-User-Id 用户 ID 调用方标识，用于用量统计；不传视为匿名
X-Feature-Code 如 role_reply 功能码，仅用于用量明细分组统计；不传或非法记为 uncategorized
Authorization Bearer sk-gw-... 项目 Token；网关校验项目、配额与模型范围。不带 sk-gw- 前缀时按旧版上游 Key 语义处理
X-Request-Id 可选，≤64 字符 调用方链路追踪 ID；不传由网关生成，并写入调用记录

集群与模型选择

集群在「大模型管理」中按模型配置
集群请求头典型用途
集群1async1主 LLM 默认池
集群2async2异步 / 后台任务常用池
集群3集群4 集群5集群6 集群7集群8 集群9
async3..async9 特殊分流或独立容量池

未传 X-Async-Type 时按 X-Purpose 回落： 不以 async 开头 → async1，以 async 开头 → async2。 每个集群按「渠道健康」中的路由策略选择模型：轮询、成本优先或延迟优先。

渠道失败时会在同集群内自动换渠道重试（连接失败、超时、429、5xx、401/403）。 连续失败达到阈值会熔断并冷却，冷却后自动半开探测；可在「渠道健康」手动重置。 400/404/422 属于请求或模型本身问题，不会换渠道重试。

模型配置了 temperature / top_p / top_k / max_tokens 时，服务端会覆盖请求体同名参数；留空则沿用客户端值。

temperature 与 top_p 互斥，只能配置一个；top_k 仅部分厂商支持。o 系列跳过采样参数，Claude 开启思考时固定 temperature=1。

模型配置输入/输出单价后，「用量明细」会显示估算成本（USD / 1M tokens）。 OpenRouter 返回 usage.cost 时按实际扣费记录，其余厂商为估算值。

cURL 示例

项目 Token + 流式请求
bash
curl -X POST "https://your-domain/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-gw-你的项目Token" \
  -H "X-Async-Type: async1" \
  -H "X-Feature-Code: role_reply" \
  -H "X-User-Id: demo-user" \
  -d '{
    "model": "",
    "messages": [
      {"role": "user", "content": "你好"}
    ],
    "stream": true
  }'

OpenAI SDK 示例

base_url 指向 /v1
python
from openai import OpenAI

client = OpenAI(
    base_url="https://your-domain/v1",
    api_key="sk-gw-你的项目Token",
    default_headers={
        "X-Async-Type": "async1",
        "X-Feature-Code": "role_reply",
    },
)

resp = client.chat.completions.create(
    model="",  # 留空由网关按集群选择
    messages=[{"role": "user", "content": "你好"}],
    stream=False,
)
print(resp.choices[0].message.content)

响应与错误

流式返回标准 SSE；非流式返回上游 JSON 信封
状态码含义处理建议
200成功流式读取 data: 事件，直到 [DONE]
400X-Async-Type、model 或 JSON 非法集群用 async1..async9，model 留空或使用合法名称
401项目 Token 无效、吊销或过期重新在「项目与密钥」创建或轮换 Token
403Token 不允许使用该模型 / 项目已停用检查 Token 的允许模型与项目状态
429项目配额超限查看 error.code，调整项目限额或等待次日 / 次月
502上游厂商返回错误网关已尝试同集群其他渠道；检查提供商地址与 Key
503所选集群没有可用模型在「大模型管理」中启用该集群模型

调用 /v1/chat/completions，model 留空，通过 X-Async-Type 选择集群。
